## Fixed in Phase 3C

| Issue | Fix |
|---|---|
| The second Redemption smoke in a Windows job (GM Admin) sometimes failed with an empty client log. `tools/smoke_redemption_login.sh` copies the client with hard links, including the `pokeverse.log` the launch test leaves in `dist/client-redemption`, so every run wrote into that one file and the next run saw the previous run's `[pv-smoke] EXIT` line and stopped its client at once | The harness deletes copied `*.log` links before starting the client and waits for the previous client process to exit (reproduced and verified locally) |
| Market: `nearOnMarket` raised a Lua error for a player with no stored market position (it split the number -1 as a string) | Type check; the player is refused instead (`MARKET AWAY REFUSED`) |
| Market listings written by another Lua state or by hand were invisible until a restart | `###MARKETALL###` reloads from the database |
| Market sell, buy and offer accepted forged counts, prices, codes and other players' listings | See `SECURITY_AUDIT.md`, Phase 3C |
| The shop refund message was sent without the player id, so `__L` could not pick the language | `shop.lua` passes `cid` |
| The task kill count was sent as "1 de 40" (Portuguese) | Sent as "1/40" |
| The smoke harness's `timeout` killed the wrapper shell and left the client running | The client is started with `exec` |
| The Windows package guard self-test wrote `required-tables.txt` with LF, which the validator now refuses | Written with CRLF |
| Any login with a language byte of 3 or more was stored in `accounts.lang_id`, and the next translated message dereferenced a missing table: a crash any client could trigger (PokeNation BUG-08) | The login byte is ignored when out of range, stored values fall back to English, `Localization::t` uses `find`, and `setPlayerLanguage` refuses unknown ids. `tools/protocol_smoke.sh` checks byte 99 and a stored `lang_id = 7` |
| The game server skipped the echoed login challenge (`SkipBytes(6)`), so any value was accepted (PokeNation BUG-68) | The challenge is kept per connection and compared; a mismatch is logged and closes the connection. The bytes on the wire are unchanged; the Redemption, legacy and Python clients still log in. `tools/protocol_smoke.sh` checks a forged echo |
| The Windows smoke reused the real `%APPDATA%` settings folder across runs | Each run passes `--user-dir` with an empty folder of its own and logs the client's exit status |

PokeNation BUG-75 (the client assert `delay >= 0` after a jump move) does not apply to PokeVerse. The Redemption client computes the jump with `std::max<double>`, and 300 jumps on its Debug build (asserts active) did not trip it. The legacy client has the `std::max<int>` form, but its RelWithDebInfo build gets `-DNDEBUG` from CMake's default flags, so the assert is compiled out and a negative delay runs at the next poll, as in the original release.

## Fixed in Phase 3

| Issue | Fix |
|---|---|
| The server didn't build with Boost 1.87+ (removed `io_service`, `deadline_timer`, `address_v4::from_string`, `io_context::dispatch`, `to_ulong`) | Ported to `io_context`, `steady_timer`, `make_address_v4`, `boost::asio::post`/`dispatch` and `to_uint`. Deprecated Boost APIs are now compile errors on every platform. |
| The server didn't build on Windows (`MAXUINT32` macro clash, XP-era `_WIN32_WINNT`, missing Winsock libraries) | `tools.cpp` rename, `_WIN32_WINNT=0x0601`, link `ws2_32`/`mswsock` |
| The Windows server had no clean shutdown | Console control handler: Ctrl+C or closing the console saves and shuts down |
| The staged Redemption package shipped upstream's bot (`mods/game_bot`, vBot 4.8), found in the Windows Release artifact of Platforms run 37609336370 | `tools/stage_redemption.sh` drops `game_bot` and its `client_mods` load entry (the `client-redemption/` subtree stays unmodified). `tools/package_client.sh` refuses any `game_bot` directory, and `validate.py regressions` guards both. |
| The status header read "Unknown, version Unknown (Unknown)" and outdated clients were sent to `http://www.psoul.net` (former #9, #10) | `resources.h`: `STATUS_SERVER_NAME` is PokeVerse; `CLIENT_VERSION_STRING` uses "TODO - POKEVERSE URL REQUIRED" |
| The server process never exited after `/shutdown` (BUG-72): `ServiceManager::stop()` was a no-op because `running` was set only after `io_context::run()` returned | `server.cpp` sets `running` before `run()`. `tools/protocol_smoke.sh` checks that the ports close and the save completes. |
| Client packets sent right after entering the game could be dropped: `ProtocolGame::parsePacket` runs on the network thread and ignored packets until `m_acceptPackets` was set, which login did only after `placeCreature` had flushed the login packets and after a database write. | `protocolgame.cpp` accepts packets from just before `placeCreature` / `sendCreatureAppear`, so early packets queue behind the login task. Guarded in `validate.py regressions`. This alone did not fix the Windows `/i` failure below. |
| The GM `/i` in the Windows protocol smoke never created items. MSYS2 rewrote the `--say "/i 35547,2"` argument into `C:/msys64/i 35547,2` when starting the native UCRT64 Python, so the server received plain chat. The same applies to `--say "/shutdown"`. | `tools/protocol_smoke.sh` exports `MSYS2_ARG_CONV_EXCL='*'`. Confirmation: the Windows server CI run after this change. |
| Harness builds could be packaged by mistake | Separate variants plus the packaging guard (`CLIENT_VARIANTS.md`) |
